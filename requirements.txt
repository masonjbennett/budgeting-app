# NOTE ON REDEPLOYS. Adding a NEW name to calculations.py and importing it from
# budget_app.py can break the deployed app with an ImportError, even though both
# files are correct and import cleanly anywhere else: Streamlit re-runs the script
# in a LONG-LIVED process, so `import calculations` can return the module already
# in sys.modules — the version from before that name existed. It happened on
# 2026-09-01 with TOP_BRACKET_START. The fix is a full container restart: "Reboot
# app" in the Streamlit Cloud dashboard, or any edit to THIS file, which changes
# its hash and forces a fresh environment. Touched 2026-09-01 for that reason.

# Pinned deliberately, after the sibling portfolio-app broke on exactly this.
# That app styled Streamlit through its internal DOM under `streamlit>=1.32.0`;
# a routine rebuild picked up a release where the widgets moved from BaseWeb to
# React Aria, 11 CSS rules silently stopped matching, and the benchmark
# dropdown rendered #E2E8F0 on white. Nothing in the repo had changed. This app
# styles Streamlit the same way, so it carries the same exposure.
streamlit==1.62.0

# plotly capped at the major this app was written against (it was last touched
# Apr 2026, when 6.7.0 was current; 7.0.0 landed 2026-08-25). Usage here is
# plain graph_objects — Figure/Scatter/Bar/Pie/Histogram/Waterfall — so the cap
# costs nothing and stops a major arriving unannounced on the next rebuild.
plotly>=5.18.0,<7.0.0

pandas>=2.0.0,<4.0.0
numpy>=1.24.0,<3.0.0

# supabase is capped at its major rather than pinned exactly: it is a network
# client, and its patches track a service that changes underneath it.
supabase>=2.0.0,<3.0.0
